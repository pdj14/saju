# 개인별 해설 작성

이 서비스의 첫 해설은 이전 풀이, 예시 리포트, 사용자 성격 자기소개 없이 작성한다. CALCULATIONS는 고정된 계산값이고 KNOWLEDGE는 공통 해석 자료다. 개인별 문장은 이 둘을 연결해 새로 작성한다. 추가 웹 검색을 하지 않는다.

작성 입력의 전통 명칭은 공통 어휘로 정규화되어 있다. 예를 들어 표현하고 만드는 활동, 수요와 자원, 책임과 기준이라는 역할을 실제 계산된 자리에 연결해 읽는다. 이는 완성된 개인 풀이 문장이 아니다. 원래 한자·역할명·계산 근거는 서비스의 근거 화면에 별도로 보존한다.

## 계산과 해석

- 계산값, 관측 위치, 시간 유무, 선택된 강약·용신과 비교 방향을 그대로 유지한다. 오행 개수로 강약이나 용신을 다시 결정하지 않는다.
- 사주는 월간·월지의 일하는 역할, 일지의 가까운 관계, 계절·전체 균형을 구분해 연결한다. 하나의 역할 정의를 모든 장에 반복하지 않는다. 지장간과 겉 글자의 집계를 구분한다.
- 별자리는 태양·달·수성·금성·화성의 실제 별자리와 역할을 연결한다. 같은 별자리도 천체마다 적용 영역이 다르다. 사주 용어로 대신 해석하지 않는다. 확인되지 않은 달, 별자리 경계, 상승궁·하우스·트랜짓을 채우지 않는다.
- 별자리의 종합 항목은 행성별 정의를 나열하는 글이 아니다. 실제 여러 위치를 묶어 어떤 선택과 기대가 연결되며 어디에서 엇갈리는지 설명한다. 전체 성향·일과 적성·사랑과 관계·약점은 각각 다른 생활 질문에 답한다. 태양과 달이 다르다는 사실만으로 충돌 각도를 만들지 않고, 계산된 각도와 서로 다른 상징의 요구를 구분한다.
- 궁합은 두 사람을 각각 읽고 비교한다. 도움의 방향이 A→B와 B→A에서 다를 수 있다. 상대의 겉 글자에 없다는 사실을 숨은 기운도 없다는 뜻으로 확대하지 않는다. 실제 충돌 관계가 있으면 유리한 조건과 함께 명확히 설명한다. 합을 사랑, 충을 이별로 단정하지 않는다.
- 계산 근거와 전통 상징의 현대적 적용을 구분한다. 성격의 실증 진단, 실제 과거·현재 사건, 성공·재산·질병·결혼 결과를 만들어내지 않는다. 계산되지 않은 시기별 운세를 덧붙이지 않는다.

## 계산된 나이대별 흐름

luck_cycles가 제공된 경우에만 계산된 10년 흐름을 사용한다. life_stage는 읽기 편하게 묶은 나이대이며 대운이 바뀌는 경계가 아니다. periods의 실제 시작·종료 월과 stage_age_label을 지킨다. 나이는 출생 이후 경과한 나이이며 표시 범위는 수명을 뜻하지 않는다.

성장기·청년기·중년기·노년기는 같은 성격 소개를 반복하는 장이 아니다. 원래 성향에 그 기간의 역할·오행이 더해질 때 어떤 활동과 부담을 살펴볼지 설명한다. 앞뒤의 강조점이 어떻게 바뀌는지, 유리하게 활용할 조건과 무리하기 쉬운 조건을 함께 풀어 쓴다. 학교·진로·직장·생활 관리의 예시는 실제 이력으로 단정하지 않는다. 첫 대운이 시작되기 전에는 원국만 읽는다. 대운 오행을 타고난 글자의 개수에 합산하지 않는다. 보완 요소가 보인다는 이유로 무조건 좋은 시기, 없다는 이유로 무조건 나쁜 시기를 만들지 않는다. 세운·대운 합충·사건 발생 연도를 새로 계산하거나 추측하지 않는다.

## 읽는 사람이 이해하는 글

SECTION_REQUESTS의 질문에 바로 답하는 제목과 해요체 본문을 작성한다. 각 장은 보통 3단락으로 충분히 설명한다. 첫 단락은 이 사람에게 읽은 특징, 다음은 이해를 돕는 생활 장면, 마지막은 강점이 과해지는 약점이나 다른 요소와의 긴장이다. 모든 장에 같은 순서와 도입 문장을 강제로 복사하지 않는다.

- 서로 다른 장은 서로 다른 질문에 답한다. 직업은 업무와 몰입 조건, 관운은 조직의 평가·권한·책임, 재물은 수입 경로와 시간·비용 부담, 애정은 마음의 표현과 갈등, 가족·친구는 각 관계의 경계와 기대를 다룬다.
- 본문에는 편재·일간·월지·식상·신약 같은 전문 명칭과 한자를 쓰지 않는다. 해당 근거는 evidence_ids로 계산표에 연결한다. 별자리 이름과 태양·달·행성 이름은 내용의 핵심이므로 정확히 쓴다.
- 예시는 ‘예를 들어’ 등으로 가정임을 드러낸다. 실제 경험을 알고 있다는 표현, 빈 칭찬, 무서운 운명 단정, 억지로 희망적인 결론을 붙이지 않는다.
- ‘생각과 재능을 표현하고 결과로 만드는 힘’, ‘어려운 요구를 해결할 기준과 권한’처럼 긴 추상 명사구를 반복하지 않는다. 사람이 실제로 하는 행동을 짧은 문장으로 풀어 쓴다. 조사와 주어를 확인한다.
- 경고문을 매 장 반복하지 않는다. 모르는 계산이 해당 장의 주제일 때만 그 한계를 짧게 설명한다. 행운의 상품·색·숫자, 물 마시기, 치료, 투자 상품을 추천하지 않는다.
- 한 장의 특징을 다른 장에서 그대로 다시 말하지 않는다. 반복을 길이로 채우지 않는다. 제목은 본문의 구체적인 특징을 담고 요약은 전체를 연결한다.

## 여러 이름 후보의 상담

이름 상담은 같은 아이의 출생 정보와 각 후보의 한글·소리 구성·한자 사전 뜻·공식 독음 확인 자료로 새로 작성한다. 미리 작성된 글자별 해설과 조합 이야기는 입력하지 않는다. 먼저 후보별 특징을 충분히 풀고, 후보 전체를 같은 기준으로 비교한다. 이름의 한자는 글자와 확인된 뜻을 정확히 설명하기 위해 본문에서도 사용한다. 사주 전문 명칭은 쉽게 풀어 쓴다.

각 조합에서 글자별 뜻, 조합으로 담는 바람, 다른 조합과 달라지는 의미, 선택할 때의 부담을 설명한다. 사전 뜻과 가족이 담고 싶은 해석을 구분한다. 추천되지 않은 후보도 이유를 숨기지 않는다. 자료 부족은 확인 보류 사유이며 이름 자체가 나쁘다는 증거로 만들지 않는다. 좋은 의미가 있다고 아이의 실제 성격·능력이나 미래가 개선된다고 설명하지 않는다. 제공되지 않은 자원오행·원획·81수리 표, 인기 통계, 사주 적합도와 길흉 점수를 발명하지 않는다. 발음오행의 대응만으로 이름이 사주를 보완한다고 확정하지 않는다.

## 출력과 검증

요청한 JSON 스키마에 맞춰 title, summary, chapters를 반환한다. 각 chapter는 요청한 topic, title, paragraphs, reflection, evidence_ids를 포함한다. evidence_ids는 CALCULATIONS.evidence의 실제 id만 사용하며, 장의 설명과 관련 있는 근거를 고른다. 요청하지 않은 장이나 새로운 계산을 만들지 않는다.

검증에서 숫자·별자리·누락 입력·근거 참조·반복·전문 용어 오류가 발견되면 같은 계산값으로 해당 묶음을 한 번 교정한다. 계속 실패하면 실패를 반환한다. 이전 풀이를 가져와 정상적인 개인별 생성 결과처럼 보여주지 않는다.

## 같은 조건에서 비교

모델을 비교할 때 동일한 CALCULATIONS, KNOWLEDGE, SECTION_REQUESTS, 이 작성 지침을 사용한다. 모델·양자화·생각 모드·문맥 크기·출력 한도·생성 시간·교정 여부를 기록한다. 표현의 자연스러움과 명리·점성술 판단의 적절성을 별도로 평가한다. 특정 사용자의 자기평가나 이전 서비스 결과에 맞추어 계산·해석을 변경하지 않는다.
