# 모아

사주에 필요한 양력 생일·출생 시간·지역과 이름을 한 번 입력하고, 지원하는 분석을 함께 읽는 한국어 웹서비스 초기 버전입니다. 사주를 명확히 표시한 메뉴, 한자와 독음을 함께 보여주는 원국 분석 리포트, 명식과 해석을 나눠 읽는 탭, 문단별 계산 근거와 후속 질문을 제공합니다.

## 실행

이 Mac에서는 `Start Moa.command`를 실행하거나 다음 명령을 사용합니다.

```sh
cd /Users/dj14.park/WorkSpace/MyLLM/sites/moa
.venv/bin/python -m api.run
```

주소: `http://127.0.0.1:8787`. 사이트의 `.env`에서 해설용 모델 연결을 선택합니다. 별도 가상환경을 사용하므로 기존 이미지·영상 환경은 수정하지 않습니다.

같은 네트워크에서 접속하려면 `.env`에 `MOA_HOST=0.0.0.0`을 설정하고 재시작합니다. 다른 기기의 브라우저에서 `http://<이 Mac의 내부 IP>:8787`을 열면 됩니다. 프런트엔드와 API를 같은 주소에서 제공하므로 별도의 API 주소 설정은 필요 없습니다. 이 Mac에서만 사용하려면 `MOA_HOST=127.0.0.1`로 바꿉니다.

다른 환경에서는 Python 3.11 이상으로 가상환경을 만들고 `requirements.txt`를 설치합니다. `.env`가 없으면 기존 Ollama 연결이 기본값입니다. `.env.example`을 복사하면 OpenRouter 설정으로 시작합니다. 이미 내보낸 환경변수는 `.env`보다 우선합니다.

## OpenRouter 무료 모델로 실행

1. [OpenRouter API 키](https://openrouter.ai/settings/keys)를 만듭니다.
2. `sites/moa/.env`의 `OPENROUTER_API_KEY=` 뒤에 키를 입력합니다. 이 Mac에는 빈 키로 파일을 준비해 두었습니다. 작업공간 최상위 `.env`와는 별도 파일입니다.
3. `Restart Moa.command`를 실행한 뒤 `http://127.0.0.1:8787`을 새로고침합니다. 새로 실행하는 환경에서는 `Start Moa.command`를 사용합니다.

```dotenv
MOA_LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=여기에_발급받은_키
OPENROUTER_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

처음 비교할 모델은 현재 모델 목록에서 JSON 구조 출력을 지원하는 무료 Nemotron 3 Super입니다. 한국어 해설 품질은 실제 결과로 평가해야 합니다. [무료 자동 라우터](https://openrouter.ai/openrouter/free)도 `OPENROUTER_MODEL=openrouter/free`로 선택할 수 있지만, 호출마다 모델이 바뀔 수 있어 동일 조건 비교에는 고정 모델을 권합니다. 응답의 `generation.calls[].actual_model`에 실제 모델을 기록합니다.

OpenRouter 요청은 `:free` 모델과 `openrouter/free`만 허용하고, 제공자 요금 상한을 입력·출력·요청 모두 0으로 보냅니다. 별도 모델 대체 목록이나 유료 모델 자동 전환은 없습니다. 키 오류·무료 이용 한도·모델 중단·JSON 출력 미지원은 오류로 안내합니다. 무료 모델 목록과 [이용 한도](https://openrouter.ai/docs/api-reference/limits)는 변경될 수 있습니다. 사주 전체는 기본 6회, 별자리는 주요 6항목 3회에 검출된 개인 천체 관계마다 1회(관계가 없으면 안내 1회), 궁합과 두 사람의 핵심 사주는 11회 생성 요청을 사용하며 교정 요청이 추가될 수 있습니다.

키는 서버에서만 읽고 브라우저에 보내지 않습니다. `.env`는 Git에서 제외합니다. 사주와 천체 계산은 계속 이 PC에서 수행하지만 OpenRouter 모드에서는 이름·출생 정보·계산값·공통 참고 자료를 외부 API에 보내 해설을 생성합니다. 서버의 개인별 결과 저장은 기존처럼 메모리에 한정합니다. JSON 스키마 출력 대신 JSON 객체만 지원하는 무료 모델을 시험할 때는 `OPENROUTER_JSON_MODE=json_object`를 선택할 수 있습니다. 이 모드는 스키마를 작성 지침으로 전달하고 응답 형식과 근거 검사는 서버에서 계속 수행합니다.

키 입력 후 연결 확인과 짧은 실제 생성 시험:

```sh
PYTHONPATH=. .venv/bin/python scripts/check_model_connection.py
PYTHONPATH=. .venv/bin/python scripts/check_model_connection.py --generate
```

첫 명령은 모델 목록과 키 인증만 확인합니다. `--generate`는 합성 입력으로 한 항목을 실제 생성하며, 최대 한 번 교정합니다. 결과는 `.runtime/model-validation/connection-sample.json`에서 확인합니다. 키를 입력하기 전의 자동 테스트는 모의 API로 검증하며 실제 모델 품질 시험과 구분합니다.

기존 Qwen으로 돌아가려면 `.env`에서 `MOA_LLM_PROVIDER=ollama`로 바꾸고 재시작합니다. `MOA_MODEL=qwen3.5:9b`, `MOA_OLLAMA_URL=http://127.0.0.1:11434`를 사용합니다. OpenRouter 모드에서는 시작 스크립트가 Ollama를 실행하지 않습니다.

## 현재 기능과 범위

- 이름: 한글 음절·초성·발음오행의 한 가지 기준을 실제로 계산합니다. 성을 함께 입력할 수 있습니다. 한글 이름을 입력하면 각 음절에 맞는 한자 선택란을 표시합니다. 사전 독음 486개에 대응하는 후보 중 한국어 뜻이 있는 글자를 먼저 보여주며 자동 선택하지 않습니다. 이름을 바꾸면 이전 선택은 지웁니다. 모두 선택한 이름 한자를 `name_hanja`로 받으며 일부만 선택했을 때에는 나머지 선택 또는 한자 없이 보기를 안내합니다. 입력한 글자는 Unicode 17.0.0 Unihan의 사전 뜻·독음으로 조회하고, 기본 뜻 339개는 자체 한국어 정리를 사용합니다. 전체 24,013개 조회 레코드를 수록하되 한국어 뜻이 없는 경우 원자료의 영문 뜻을 보여줍니다. 뜻 미확인·독음 불일치도 표시하며 두음법칙을 자동 판정하지 않습니다. 한글 이름만으로 한자나 원획·81수리·인명용 한자 적합 여부·통계 순위를 만들지 않습니다. 뜻과 독음에 근거한 이름 상담·같은 소리의 다른 한자 조합 추천을 제공합니다. 자원오행·원획·81수리 길흉을 포함한 전체 전문 작명 엔진은 아직 제공하지 않습니다.
- 사주: `korean-saju 0.3.0`이 간지·일간·십성·지장간·십이운성·합충형파해·강약·격국·용신·희신을 계산합니다. 명식은 시·일·월·년 순서로 표시합니다. 주된 강약은 엔진의 억부 분류, 보조 배점은 별도 항목으로 공개하며 두 결과가 다르면 함께 표시합니다. 시간 미입력 시 시주를 만들지 않고 강약·격국·용신 확정 안내를 생략합니다. 양력, 한국 시간, 전국 시군구·읍면동 대표지점의 경도 보정, 야자시 분리 기준입니다. 1900–2050년 입력을 지원하며 2000–2027년 밖 절기는 근사 계산이라 경계 시각은 추가 확인이 필요합니다. 전문 상담 수준의 판단 품질은 별도 검증이 필요합니다.
- 궁합: 두 사람의 일간 상징과 일지 육합·육충만 실제 비교합니다. 종합 궁합 점수나 관계 성패를 생성하지 않습니다.
- 별자리: MIT Astronomy Engine 2.1.19로 태양·달·수성·금성·화성·목성·토성·천왕성·해왕성·명왕성의 지심 황경을 계산해 열대황도 12궁에 배정합니다. 주요 5종 각도(0·60·90·120·180도)를 모든 쌍에서 허용 범위 ±4도로 검출합니다. 이는 자체 선택한 오브이며 보편 기준이나 운세 점수가 아닙니다. 시간 미입력 시 태양·8개 행성의 정오 참고 위치만 표시하며 해당 날짜를 매시간 검사해 경계일의 가능한 별자리를 표시합니다. 달과 각도는 생략합니다. 한국표준시 UTC+9 고정이므로 과거 서머타임 적용 시각은 별도 검증이 필요합니다. 상승궁·하우스·트랜짓·인도 점성술·자미두수는 이 버전에서 계산하지 않습니다.
- 풀이: 사주·별자리·궁합은 `api/model_readings.py`에서 계산값과 공통 참고 지식만으로 설정한 모델이 본문을 새로 작성합니다. 기존 개인 풀이·예시 리포트·자기소개를 첫 생성 입력으로 사용하지 않습니다. `skills/moa-readings/SKILL.md`를 런타임 작성 지침으로 읽고, 주제별 묶음으로 생성해 전문 용어·반복·잘못된 참조·일부 숫자 및 별자리 오류를 검사합니다. 한 번 교정해도 실패하면 503 오류를 반환하며 규칙 문장을 대신 사용하지 않습니다. 생성 대기 중에는 계산표와 대기 안내만 제공합니다. 이름 상담은 기존 별도 경로를 유지합니다. 자동 검사는 모든 잘못된 해석을 검증하는 장치가 아니며 전문가 검증은 별도입니다.
- 관심 이름: 사용자가 담은 한글 이름만 브라우저에 보관합니다. 생일·질문은 함께 저장하지 않습니다.

## 사주 리포트 화면

생년월일을 입력한 사주·이름·별자리 진입점은 같은 입력의 통합 리포트를 반환합니다. 이름만 입력하면 기존 이름 풀이를 제공합니다. 사주 풀이 / 계산 근거 / 별자리 / 이름의 네 탭, 입력별 분석 범위, 오행 분포, 십성 구성, 강약·격국·용신과 보조 배점, 합충형파해, 용어 설명을 제공합니다. 각 해석 문단에 근거 ID를 연결합니다. 점성술의 천체 표·각도·두 체계 비교와 이름의 음절·초성 표를 같은 리포트에 담습니다. 년지 기준 띠는 입춘 경계 기준임을 명시합니다. 사주 오행과 서양 점성술의 요소를 합산하거나 정확도·성공 확률로 바꾸지 않습니다. 후속 질문은 관련 주제의 출처를 함께 검색합니다. 브라우저 인쇄 기능으로 PDF 저장을 선택할 수 있습니다. `dist/assets/report-example.json`은 명시적으로 표시한 합성 예시(박지민, 2004-05-15 10:30 서울)의 실제 계산값과 모델이 새로 생성한 본문이며 방문자 입력으로 계산한 결과가 아닙니다. 모델과 입력·스킬 해시는 예시의 generation에 기록합니다.

## 지식 자료

`knowledge/notes.json`은 출처를 확인하고 직접 작성한 짧은 요약과 자체 편집 원칙입니다. 상업 서비스나 전문서적의 풀이를 복제한 데이터셋이 아닙니다. 현대 저자의 전체 글·도서는 수록하지 않았습니다.

`knowledge/cafe-ontology.ttl`은 Dangamsoft가 공개한 CAFE Ontology의 고정 커밋입니다. CC BY 4.0에 따라 출처를 표시합니다. 공개 개념과 관계만 포함하며 비공개 엔진·가중치·해석 템플릿은 포함하지 않습니다. `knowledge/provenance.json`에 원문 URL·커밋·SHA-256·이용 조건을 기록했습니다. 서버가 한국어 개념 이름과 설명을 읽어 주제별 자료와 함께 검색 인덱스로 구성합니다.

주요 참고: [CAFE Ontology](https://github.com/dangamsoft/cafe-mcp/tree/main/ontology), [korean-saju](https://github.com/glee1228/korean_saju), [Astronomy Engine](https://github.com/cosinekitty/astronomy), [이름의 음양오행 구성 원리](https://namestory.kr/m/bbs/board.php?bo_table=sub3_1&page=17&wr_id=19), [대법원 인명용 한자 조회](https://efamily.scourt.go.kr/index.jsp).

## 이름차트 같은 사이트에서 연결

외부 사이트에 다음 URL을 링크로 넣으면 방문한 사용자의 이름이 입력란에 채워집니다. 실제 외부 사이트의 링크는 이 프로젝트에서 수정하지 않았습니다. 제휴·API 연결을 뜻하지 않습니다.

```text
https://YOUR-DOMAIN/?from=namechart&name=하린&surname=김
```

`name` 또는 `candidate`, 선택적인 `surname`만 받습니다. URL의 이름은 한글로 검증하고 HTML을 실행하지 않습니다. 생년월일은 연결 URL에 넣지 않습니다. 결과 화면의 이름 통계 링크는 공개 네임차트의 해당 이름 페이지를 엽니다. 통계 데이터를 복제하거나 숫자를 생성하지 않습니다.

## 호스팅과 실제 모델 연결

Sites에 배포한 `dist`는 디자인·상호작용 미리보기입니다. `/api/health`가 없는 호스팅 환경에서는 **예시**임을 명시한 풀이 화면을 표시하며 실제 개인 분석 결과로 가장하지 않습니다. `window.MOA_API_BASE`를 실제 HTTPS API 주소로 설정하면 동일 프런트엔드가 `/api/read`, `/api/ask`를 호출합니다. API 서버의 `MOA_ALLOWED_ORIGIN`도 사이트의 정확한 origin으로 설정해야 합니다.

실제 풀이와 질문 API는 이 Mac의 8787번 주소에서 동작하며, 해설 생성은 설정한 모델 제공자를 사용합니다. 외부 방문자에게 제공하려면 공개 HTTPS 백엔드, 모델 서버의 인증·속도 제한·운영 환경을 별도로 구축해야 합니다. 이 초기 버전은 인터넷에 로컬 모델을 노출하지 않습니다. 새 Sites 배포는 소유자 전용이며 공개 링크를 외부 사이트에 넣기 전에 대상에 맞는 호스팅 구성이 필요합니다.

API 세션은 메모리에 최대 100개, 30분만 유지하며 디스크에 개인 입력을 기록하지 않습니다. 추가 질문은 한 세션에 최대 10회입니다. 계정·결제·방문자 추적은 없습니다.

## 해석과 한자 자료의 범위

`api/interpretation.py`는 일간·월지·십성 조합·주된 강약·격국·용신을 연결하는 공개된 자체 편집 규칙입니다. 여섯 장의 예시 본문은 일상적인 한국어로, 정의를 나열하는 데서 끝내지 않고 주의점과 구체적인 생활 예를 함께 설명합니다. 자리 수만으로 세력의 강약을 판정하거나 식상생재·상관견관의 길흉을 확정하지 않습니다. 고전의 분류와 전체 구조 읽기는 적천수 원문을 참고하고 현대 기질·업무·관계·생활 적용은 자체 응용임을 구분합니다. `dist/method.html`에서 사용한 기준과 검증 범위를 확인할 수 있습니다.

`api/astrology_interpretation.py`는 실제 태양·달·수성·금성·화성의 위치를 역할별로 풀이하며 사주와 합산하지 않습니다. `knowledge/hanja-unihan.json`, `hanja-provenance.json`, `UNICODE-LICENSE.txt`는 공식 Unicode 17.0.0 원자료, SHA-256, 필드와 라이선스를 기록합니다. 이름 사전 정보와 전문 작명 엔진은 구분합니다.

후속 질문의 실제 원국 풀이에서 보이지 않는 십성을 언급하면 한 번 다시 작성합니다. 재작성도 출력 검사를 통과하지 못하면 질문 주제에 맞는 이미 확인된 리포트 본문을 돌려주고 `answer_mode=grounded_report`로 구분합니다. 모델 연결 오류는 이 경로로 숨기지 않습니다. 이것은 완전한 의미·해석 검증 장치가 아닙니다.

첫 요약은 실제 계산에서 만든 문장을 그대로 표시합니다. 후속 답변에서 단일 십성·그룹의 명시적 자리 수가 계산과 다르면 다시 작성합니다. 복합 표현 전체를 검증하는 장치는 아닙니다.

한자 후보 파일은 `.venv/bin/python tools/build_hanja_choices.py`로 같은 사전에서 재생성합니다. 호스팅 미리보기에서도 서버 없이 글자별 선택이 동작합니다. 한국어 미정리 후보는 이를 표시하며 사전 원문을 펼쳐 확인할 수 있습니다. 선택 가능한 후보가 인명용 한자 목록과 같다는 뜻은 아닙니다.

기본 풀이와 일반 후속 질문은 전문 용어를 앞세우지 않고 생활 예로 설명합니다. 일반 질문의 답에 명리 용어가 들어가면 한 번 다시 작성하며, 명리 용어 자체를 물은 질문은 뜻을 설명할 수 있습니다. 자세한 계산은 별도 탭과 펼침 영역에 유지합니다.

## 상세 원국 풀이

사주 본문은 예시 기준 약 8,000자, 열세 영역의 각 4–7개 문단으로 구성합니다. 전체 인상·성향·매력·솔직한 약점·일·재물·연애·가족·친구·오행·환경과 균형·마지막 한마디를 친근한 서술로 연결합니다. 오행과 격국 설명은 뒤쪽 이야기와 계산 근거에 놓고, 처음에는 사람이 어떤 모습으로 힘을 쓰는지 풀어줍니다. 목차는 필요할 때 펼쳐 원하는 이야기로 이동합니다. 기준 글자의 한자·독음과 뜻, 출생 절기 월, 실제 격국과 선택 근거, 드러난 세부 역할의 차이, 강점과 과해질 때의 모습, 재물과 관계, 용신·희신의 뜻을 연결해 설명합니다. 용어를 단순히 없애지 않고 등장한 곳에 뜻을 붙입니다. 예는 해석을 이해하기 위한 가정이며 방문자의 현재 경험을 추측한 결과가 아닙니다.

`interpretation_frame`은 `kind=birth_chart`, `uses_current_date=false`, `includes_luck_cycles`는 시간·계산 기준 입력에 따라 달라집니다. 실제 대운은 `api/luck_cycles.py`에서 계산하며 오늘의 운세·세운·연운·일진·사건 결과는 계산하지 않습니다. 같은 출생 정보와 규칙이면 핵심 본문도 같습니다. AI 답변도 현재 상황이나 이번 주의 운세로 바꾸지 않도록 안내하고 일부 표현을 검사합니다. 전문 상담의 전체 정확성을 검증하는 장치는 아닙니다.

참고 서비스 saju-kid.com의 공개 메뉴와 사용자가 제공한 풀이 예시에서 친근한 문체와 주제의 폭을 참고했습니다. 해석 본문은 자체 문장이며 전문 상담 규칙을 수입한 것이 아닙니다. 예시의 출생 글자는 실제 사용자 정보로 저장하거나 대체하지 않았습니다. 과거 가족사·건강·금전 성과를 단정하거나 계산하지 않은 신살·대운·행운 숫자를 생성하지 않습니다.

## 아이 이름 상담

아이 이름 화면에는 성·이름과 글자별 한자 선택, 선택한 성의 한자, 이름에 담고 싶은 마음, 생년월일·시각·출생지를 표시합니다. 출생 정보 입력란은 접지 않습니다. `surname_hanja`는 성과 같은 글자 수로 검증하고 `naming_preference`는 허용한 다섯 선택만 받습니다. 성과 이름의 한자는 독립적으로 바뀌며 추천 조합 선택 시 출생 정보와 성·바람은 유지합니다.

`api/naming.py`가 글자별 뜻·공식 독음 확인·전체 뜻의 바람·소리·출생 참고 관계·추천 조합을 구성합니다. `knowledge/naming-editorial.json`은 한국어 뜻이 확인된 글자를 네 가지 바람으로 편집한 자체 후보표입니다. 추천은 같은 한글 이름을 유지하고 공식 조회에서 해당 독음으로 확인한 후보만 사용합니다. 추천 순서는 바람과 뜻의 연결 기준이며 운세 점수나 사주 보완 순위가 아닙니다. 다섯 글자 이상이거나 공식 독음과 사전 뜻을 함께 확인한 후보가 없는 음절은 조합을 만들지 않습니다. 편집한 주제 후보표는 정렬 기준이며 검색 허용 목록이 아닙니다. 사전 전체와 공식 독음 자료를 조인하고, 한국어 뜻이 없는 경우 제공된 영문 정의만 해설의 번역 근거로 사용합니다. 비교용 세 조합은 전체 한자 목록을 뜻하지 않으며 각 음절의 다른 글자도 함께 비교하도록 고릅니다.

`tools/update_name_registry.py`는 전자가족관계등록시스템의 공개 인명용 조회에서 사전 뜻이 있는 독음 전체를 확인하고, 글자 목록·독음·조회일·응답 SHA256만 저장합니다. 법원 조회의 사전 설명문·0으로 반환되는 획수 필드는 사용하지 않습니다. 같은 날 성공한 독음은 재사용하며 누락된 독음은 조회하지 않은 것으로 남깁니다. 조회일 스냅샷은 최종 신고 판정을 대신하지 않습니다. `tools/build_hanja_choices.py`는 이 자료의 확인 상태를 선택 후보에 함께 표시합니다.

`POST /api/name/preview`는 생일 없이도 즉시 이름 리포트를 반환합니다. 이름과 생일을 함께 넣으면 통합 리포트에서 이름 탭이 먼저 열립니다. 설정한 모델은 확인된 이름 보고서로 추가 설명하고, 근거 밖의 한자·조합·길흉 점수·성공 보장은 검사 후 재작성합니다. 검사를 통과하지 못하면 해당 이름 리포트에서 근거 문장을 반환합니다. 외부 비공개 사이트는 이름 상담 예시이며 실제 모델 연결은 서버 설정을 사용합니다.

## 수채화 노트와 시기별 풀이 (v8)

`notebook.css`는 로컬 Nanum Pen Script와 Gowun Batang의 손글씨 제목·메모, 크림 종이·파스텔 테마를 적용합니다. 긴 본문은 Pretendard로 읽기 쉽게 유지합니다. 수채화 그림은 built-in imagegen으로 만든 장식입니다. 폰트 라이선스는 assets의 OFL 파일에 있습니다.

`reading_scenes.py`의 열 가지 십성별 생활 장면을 실제 월지·월간·일지에 연결합니다. 13개 본문에서 뜻, 실제 글자·한자 근거, 장점과 약점, 일·가족·친구의 예시를 설명합니다. 전문 상담 정확도나 과거 사건을 검증한 데이터는 아닙니다.

Profile.gender는 선택값 `male` 또는 `female`이며 이름에서 추측하지 않습니다. 출생 시간과 함께 넣으면 Daewoon의 순역·절기 간격·첫 나이를 계산해 10년 흐름과 4개 생활 단계를 반환합니다. 엔진 첫 엔트리의 개월 오프셋을 전체 구간에 유지하고 13개월을 정규화합니다. 대운 글자는 원국 집계에 더하지 않습니다. 대운 후속 질문은 실제 계산한 설명을 반환합니다. 테스트: `PYTHONPATH=. .venv/bin/python -m unittest discover -s tests -v`.

8.1 해석 교정: 식신을 반복 업무로 제한하던 문장을 제거하고 표현·창작·제작을 포함하도록 수정했습니다. 직업·재물은 월지와 월간의 조합을 사용하며 관계 기준은 일지를 구분합니다. 관운을 별도 장으로 추가하고 조직의 평가·권한·책임을 설명합니다. 입력 시각의 표준시·경도 보정·경도+균시차 근사 보정을 비교해 일주·시주가 달라지면 표시하지만 기존 본문 계산 기준을 자동 변경하지 않습니다. 실제 사용자의 자기 평가로 해석을 수정하지 않습니다. 호스팅 미리보기에서 개인 입력을 고정 예시로 대체하는 동작을 제거했습니다. 실제 계산은 로컬 API에서 제공합니다.

8.2 궁합: 두 개의 전체 명식·개인 풀이를 유지하고 확정 용신과 상대 겉 글자의 오행을 양방향으로 비교합니다. 일지끼리의 육합·육충·파·해·형을 주요 관계로 표시하며 다른 자리의 두 글자 지지 관계는 별도 근거 표에 기록합니다. 관계의 성패나 점수, 합화·삼합·삼형 성립, 공통 대운은 판정하지 않습니다. 보완 후보와 마찰 조건을 함께 표시하고 애정·대화, 돈·일정·역할의 차이를 실제 일지·월간·월지에 연결합니다. 개인 풀이의 약점에는 강약과 실제 역할 조합에 따른 불리한 활동 조건을 별도 표시합니다. `/api/compatibility/preview`와 `/api/read`의 궁합 리포트, `/api/ask`의 비교 설명은 동일 규칙을 재사용하며 모델의 추측으로 보완·마찰 결과를 바꾸지 않습니다. 두 공개 화면 예시는 합성 입력이며 방문자의 개인 입력과 구분합니다.

## 출생지와 읽기 쉬운 해설 · v8.3

출생지는 기상청 공개 자료의 3,824개 대표지점(시군구·읍면동과 기존 도시 3개)을 오프라인 목록으로 제공합니다. 시·도 → 시·군·구를 선택하고 읍·면·동은 선택적으로 좁힙니다. 서울을 수도권 전체로 사용하지 않습니다. 기존 API의 seoul/busan/jeju 좌표는 보존하지만, 새 입력 화면에서는 지역을 먼저 고르게 합니다. 이름·사주·별자리와 궁합의 두 사람 모두 같은 목록을 사용하며 지역 ID가 실제 경도 보정에 연결됩니다. 행정구역 대표지점이므로 출생 건물의 정확한 좌표는 아닙니다. 해외 시간대·역사적인 시간대/DST는 아직 추가 검증이 필요합니다. `scripts/build_birthplaces.py`와 `knowledge/birthplaces-provenance.json`에 원문·가공·SHA-256·공공누리 제1유형 출처표시를 기록합니다. 자료 출처: [기상청 단기예보 공개자료](https://www.data.go.kr/data/15084084/openapi.do).

사주 13개 항목과 궁합 6개 항목의 본문은 실제 계산된 역할을 생활의 말로 풉니다. 편재·일간 등의 전문 이름, 한자와 자리 수는 펼쳐 보는 계산 근거에 유지합니다. 특징 → 드러나는 생활 장면 → 장점이 과해지는 약점 → 서로 다른 조건의 순서로 자체 문장을 구성합니다. 실제 경험·성공·이별을 지어내거나 해설을 자기소개에 맞춰 계산을 변경하지 않습니다. 궁합의 기운 비교는 ‘서로에게 주는 도움’에서만 설명하고 ‘잘 맞는 순간’에서는 공통의 기대와 서로 다른 강점을 비교합니다. 제목을 눌러 본문을 펼칠 수 있고 인쇄할 때는 전체 본문을 엽니다.

별자리 진입점은 별자리 제목·요약과 별자리 해설 탭을 먼저 엽니다. 같은 생일의 사주는 다른 탭에서 읽습니다. 태양·달·수성·금성·화성의 실제 별자리 위치, 태양과 달의 차이, 개인 천체 사이의 검출 각도를 역할별 생활 예시로 풉니다. 시간이 없으면 달과 각도를 임의로 채우지 않고, 하루 안에서 별자리가 바뀌는 행성은 경계임을 표시합니다. 별자리 화면의 기본 후속 질문은 별자리 해설을 사용하며 사주 본문으로 대체하지 않습니다.

## 기존 풀이 없이 개인별 본문 생성

사주는 11개 항목, 별자리는 전체 성향·일과 적성·사랑과 관계·약점의 4개 종합 항목과 계산된 천체 각도 해설을 작성합니다. 궁합은 6개 비교 항목과 두 사람 각각의 6개 핵심 사주 항목을 독립적으로 생성합니다. 사주와 별자리의 다른 탭은 같은 정보로 별도 생성하는 버튼을 제공하며, 아직 생성하지 않은 체계에 기존 해설을 끼워 넣지 않습니다. 계산값과 시간 보정 방식은 변경하지 않습니다. 출생 시간과 대운 계산 기준을 선택하면 성장기·청년기·중년기·노년기를 실제 10년 대운 경계에 연결해 각각 새로 작성합니다. 첫 대운 전에는 원국만 읽으며, 표시 나이대를 대운 경계나 사건 발생 연도로 바꾸지 않습니다. 대운 계산표는 유지하고 종전의 설명 문장은 입력하지 않습니다.

첫 생성 입력은 명시적인 필드 목록으로 추려 `CALCULATIONS`, 공통 `KNOWLEDGE`, 항목별 `SECTION_REQUESTS`로 구성합니다. 월간·월지·일지·시주의 실제 역할과 겉 역할의 집계를 별도로 전달합니다. 궁합의 방향별 비교에서는 작성된 `text`를 제외하고 실제 용신·상대 겉 구성의 일치·일지 관계를 전달합니다. 별자리는 계산 위치·실제 각도와 공통 별자리 어휘를 사용합니다. `chapters`, `interpretation`, 기존 제목·요약, 사용자의 이전 서비스 풀이를 입력으로 읽지 않습니다.

생성 결과는 메모리에 최대 32개, 30분 유지합니다. 모델·스킬·계산값·참고 지식·요청 항목으로 키를 만들며 개인 입력과 결과를 디스크에 자동 저장하지 않습니다. 후속 질문도 같은 계산 자료에서 새로 설명합니다. 모델 태그·문맥·출력 한도·스킬과 입력 해시·생성 시간·교정 여부를 `generation`에 반환합니다.

검증: `PYTHONPATH=. .venv/bin/python -m unittest discover -s tests -v`.
설정한 모델의 전체 해설 비교: `PYTHONPATH=. .venv/bin/python -u scripts/check_model_readings.py`.
비교 스크립트는 코드에 명시된 합성 입력만 사용하며 `.runtime/model-validation/<provider>/`에 출력과 측정값을 기록합니다. `--services saju` 등으로 한 서비스를 선택할 수 있습니다. 고객의 출생 정보를 이 스크립트에 넣지 않습니다. 같은 조건의 모델 비교에는 저장된 첫 생성 입력 구조와 작성 스킬을 사용합니다.

OpenRouter 실험 예시는 합성 출생 정보의 실제 모델 출력입니다. 누락된 항목을 모델로 독립 재생성해 반영한 경우 `generation.section_revisions`에 입력 해시와 호출 내역을 남깁니다. 기존 본문을 재생성 입력으로 제공하거나 사람이 모델 문장을 대신 쓰지 않습니다. 별자리의 여러 천체 관계는 각각 독립 생성하여 한 장에 담고, 궁합 보완 항목은 방향별 실제 구성 비교에 필요한 자료만 전달합니다. 무료 모델의 문체·해석 품질이 유료 상담 수준으로 검증됐다는 뜻은 아닙니다.


## 여러 이름 후보 상담

이름 상담에서 첫 이름과 추가 후보 4개를 입력할 수 있습니다. 공통 생년월일·출생 시간·지역과 성을 사용하며 후보별 한자는 선택 사항입니다. `/api/read`의 `name_candidates`는 추가 후보의 `{name, name_hanja}` 배열이고 첫 이름은 `profile`에 둡니다. 같은 이름은 한 번만 받습니다.

`api/name_readings.py`가 확인된 사전 뜻·공식 독음 조회 자료·소리 구성·출생 명식만 모델에 전달합니다. 글자별 기성 해설, 조합 이야기와 이전 개인 리포트를 작성 입력에 넣지 않습니다. 같은 아이의 출생 해설을 공통으로 한 번 작성하고, 이름마다 소리와 한자 조합의 상세 해설을 각각 새로 만듭니다. 전체 후보의 비교도 사전 뜻·공식 독음·가족의 바람·실제 음절 구성 원자료로 별도 생성합니다. 초성 오행 대응을 이름의 사주 적합도나 추천 순위에 사용하지 않습니다. 추천과 아쉬운 점을 함께 보여주며 확인된 한자 조합이 없는 후보는 한자 추천을 보류합니다. 이는 한글 이름 자체가 나쁘다는 판정이 아닙니다. 자원오행·원획·81수리의 판정 자료는 아직 연결되지 않았고 이름별 사주 적합도나 길흉 점수를 만들지 않습니다.

검증 실패는 한 번 교정 후 오류로 반환하며 기성 풀이로 대체하지 않습니다. 계산 미리보기는 새 해설이 준비 중임을 표시합니다. 후속 질문도 후보별 원자료로 모델이 새로 답합니다. 검증용 합성 입력 실행: `.venv/bin/python -m scripts.check_name_readings`.

## 한자 검색과 후속 질문

추천 생성은 `dictionary_options`에서 사전 독음과 법원 조회 독음을 함께 검색합니다. 공식 자료에는 있지만 Unihan 독음에 누락된 조합도 선택창에 포함합니다. `率`은 `솔`에서 거느림·이끎, `률/율`에서 비율로 뜻을 구분합니다. 한국어 뜻의 미정리, 공식 독음의 미조회, 추천 조합의 미포함은 각각 별개이며 이를 한자 부재로 설명하지 않습니다. 후속 질문은 기존 세 추천만 재사용하지 않고 입력 음절의 사전 후보를 다시 조회합니다. 독음별로 다시 확인한 조회일은 `reading_checked_at`에 저장하고 전체 조회일과 구분합니다.
